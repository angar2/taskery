# GIT_RULE

> 이 리포의 git 규칙이다. 맨 위 표는 taskery 명령이 읽어 그대로 따르고, 나머지 글은 에이전트가 읽고 따른다.
> 이 리포만의 규칙은 표의 값을 고치거나 `GIT_RULE.local.md`에 적는다.

| 항목 | 값 |
|---|---|
| 통합 브랜치 | `dev` |
| 브랜치 이름 | `{type}/{dev}_TASK-{num}_{slug}` |
| 커밋 메시지 | `{tag}: [TASK-{num}] {summary}` |
| 병합 방식 | `no-ff` |

- **통합 브랜치**: 빈 폴더에서 `init`이 만드는 부모 브랜치 이름이다. 기존 리포에서 태스크의 부모는 언제나 본진(리포 원래 폴더)이 서 있는 브랜치다.
- **브랜치 이름**: `{type}`은 태스크 유형, `{dev}`는 작업자 식별자, `{num}`은 세 자리 태스크 번호, `{slug}`는 영문 kebab-case 이름이다. `{dev}`를 빼면 작업자 식별자를 받지 않는다.
- **커밋 메시지**: 첫 줄 형식이다. `{tag}`는 아래 커밋 태그, `{summary}`는 medium·large면 `Phase 1 - <Phase 이름>`, small이면 태스크 제목이다. 둘째 줄부터는 명령이 파일 목록과 `- 사유: <사유>`를 붙인다.
- **병합 방식**: `no-ff`(병합 커밋을 남긴다) 또는 `ff-only`. 명령은 로컬 병합만 한다.

---

## 브랜치

| 브랜치 | 용도 |
|---|---|
| `main` | 프로덕션 |
| `dev` | 통합 개발 — 태스크가 병합되는 기본 부모 |
| 태스크 브랜치 | 태스크 하나만 담당한다. 부모에서 갈라져 부모로 병합된다 |

### 태스크 유형

| 유형 | 뜻 |
|---|---|
| `feature` | 새 기능 |
| `bug` | 버그 수정 |
| `improve` | 기존 기능 개선 |
| `refactor` | 동작을 바꾸지 않는 구조 정리 |
| `docs` | 문서 |
| `chore` | 설정·의존성 등 잡일 |

### 작업자 식별자

실제 작업자 이름을 쓴다. 예: 사용자 `angar2`, Claude `claude`, 그 밖의 AI는 그 이름(`codex` 등).

## 커밋

### 커밋 태그

| 태그 | 유형 |
|---|---|
| `feat:` | feature |
| `fix:` | bug |
| `improve:` | improve |
| `refactor:` | refactor |
| `docs:` | docs, chore |

### 예시

```
feat: [TASK-001] Phase 1 - 사용자 인증 로직

- src/auth/login.ts
- src/auth/session.ts
- 사유: 기존 세션 방식의 한계로 토큰 인증으로 바꾼다
```

- 커밋은 `commit-task`가 한다. 커밋 대상은 코드뿐이다 — taskery 파일(`.project/` 등)은 git 밖이다.
- 병합 커밋 메시지는 git 기본 메시지를 쓴다.

---

## 금지

- 비밀값(`.env`, API 키 등)을 커밋하지 않는다.
- 여러 태스크를 한 브랜치에서 하지 않는다.
- 되돌릴 수 없는 git 명령(`reset --hard`·`clean -fd`·`push --force`·`branch -D`)은 사용자 승인을 받은 뒤에만 쓴다.
