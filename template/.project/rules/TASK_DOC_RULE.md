# TASK_DOC_RULE

> 태스크 문서를 쓰는 법이다. `task-plan`이 헷갈릴 때 읽는다.

## 1. 모양

`prepare-task`가 `.project/plans/<플랜>/tasks/<NNN>_<slug>.md`를 만든다.

```markdown
# TASK-012 설정 화면 저장 버튼 색 변경
<!-- taskery: plan=001_mvp type=improve size=small switch=plan,dev,test range=끝까지 parent=dev by=taskery -->

| 시작·기획 | 개발 | 테스트 | 닫기 |
|---|---|---|---|
| ✅ 2분 | ✅ 3분 | ⏳ | – |

## 목표
## 완료 기준
## 만질 파일
## 결정
## 결과
```

- **맨 위 두 줄(메타)과 단계 표는 명령이 쓴다.** 손대지 않는다. 범위가 바뀌면 다음 태스크 명령에 `--range "<새 범위>"`를 붙인다.
- medium·large는 `## 요구사항`(목표 아래)과 `## Phase`(만질 파일 아래)가 더 있다.
- 전체 15~30줄이면 충분하다.

## 2. 절마다 쓰는 법

| 절 | 쓰는 법 |
|---|---|
| `## 목표` | 무엇을 왜 하는지 한두 줄. 첫 줄이 small 커밋의 사유와 변경 기록 요약이 된다 |
| `## 요구사항` | (medium·large) 정리한 요구 목록 |
| `## 완료 기준` | 실사용 테스트 시나리오. 아래 3절 |
| `## 만질 파일` | 한 줄에 `- 경로` 하나. 설명은 ` — ` 뒤에 적는다. 폴더는 `src/auth/`처럼 끝에 `/` |
| `## Phase` | (medium·large) 아래 4절 |
| `## 결정` | 다른 선택지가 있었고 나중에 "왜 이렇게 했지"를 물을 만한 결정만 `무엇을 정했나 — 왜` 한 줄. 없으면 비운다 |
| `## 결과` | `test-scenario`가 시나리오 결과를 한 줄씩 붙인다. 직접 쓰지 않는다 |

`approve-plan`은 목표와 만질 파일이 있는지, 테스트가 켜져 있으면 완료 기준이 1~5개인지 본다.

## 3. 완료 기준

```markdown
## 완료 기준
1. [AUTO] 설정 화면 → 저장 버튼을 본다 → 버튼이 파란색으로 보인다
2. [USER] 설정 화면 → 이름을 바꾸고 저장 → 목록에 바뀐 이름이 보인다
```

- 한 줄 형식은 `<번호>. [AUTO|USER] 시작 → 행동 → 기대하는 끝 상태`, 최대 5개. `test-scenario`의 번호는 이 순서다.
- `[AUTO]`는 AI가 실행해 확인하고, `[USER]`는 사용자가 눈으로 확인한다.
- 시나리오 하나에 의도 하나, 한 번의 실행 흐름이다. 기대값은 사용자가 화면에서 보는 결과로만 적는다.
- 실행 방법(쿼리·훅·명령)은 적지 않는다. 내부 값(DB 행·로그·픽셀)은 코드 테스트의 몫이다.
- 무언가를 없애는 태스크는 대신 보여야 할 것을 함께 적는다.
- 이 태스크 브랜치에서 실제로 해 볼 수 있는 것만 적는다.

## 4. Phase (medium·large)

```markdown
## Phase
### Phase 1 — 로그인 API
- 파일: `src/auth/login.ts`, `src/auth/session.ts`
- 사유: 토큰 인증으로 바꾼다

### Phase 2 — 로그인 화면
- 파일:
  - `src/ui/LoginForm.tsx`
- 사유: 새 API를 화면에 잇는다
```

- `commit-task`가 Phase마다 커밋 하나를 만든다. 파일은 한 줄에 쉼표로, 또는 들여쓴 목록으로 적는다.
- 한 파일이 여러 Phase에 걸치지 않게 나눈다. 걸치면 앞 Phase 커밋에 들어가고 메시지에 "(Phase 1·2 변경 포함)"이 붙는다.
- 목록에 없는 파일(잠금 파일 등)은 마지막 Phase 커밋에 들어가고, 병합 확인 요약에 "계획 확인 뒤 추가된 파일"로 보인다.
- small은 Phase 없이 커밋 하나다.

## 5. 부속 자료

화면 캡처는 태스크 문서 옆 `screenshots/`, 목업은 `mockup/`에 둔다. 처음 쓸 때 만든다.
