# BACKLOG

> 이 프로젝트에서 발견한 문제와 할 일을 모으는 곳이다. 백로그는 이 파일 하나뿐이다.

## 쓰는 법

1. 새 항목은 `taskery backlog-add "<제목>"`으로 만든다. 명령이 번호·등록일·상태를 채운 빈 양식을 `## 열린 항목` 맨 위에 넣는다. 번호는 직접 짓지 않는다.
2. 필수 칸은 반드시 채우고, 모자라면 사용자에게 묻는다. 선택 칸은 대화·작업 맥락에 근거가 있으면 적거나 제안하고, 근거가 없으면 적지 않는다. 칸을 채우려고 지어내지 않는다. `<…>`를 남기지 않는다.
3. 등록할 때는 코드를 깊게 파지 않는다. 자세한 분석은 태스크의 계획 단계에서 한다.
4. `상태`와 `연결 태스크`는 명령이 바꾼다. `보류`·`취소`만 직접 적는다.
5. 연결 태스크가 모두 닫히고 그중 하나 이상이 끝난(포기가 아닌) 항목은 명령이 `## 끝난 항목`으로 옮긴다. 모두 포기로 닫혔으면 `대기`로 되돌린다. 평소에는 `## 열린 항목`만 읽는다.

## 항목 양식 (명령이 넣는 모양)

```
### BL-<번호> [<종류>] <제목>
- 상태: 대기
- 등록: <날짜>
- 현상: <현상>
- 연결 태스크: –
```

| 칸 | 필수 여부 | 채우는 규칙 |
|---|---|---|
| 번호·등록일·상태·연결 태스크 | 자동 | 명령이 채운다 |
| 종류 | 필수 | `bug`·`improve`·`feature`·`refactor`·`docs`·`chore` 중 하나 |
| 제목 | 필수 | 한 줄. 무엇이 문제인지, 또는 무엇을 원하는지 |
| 현상 | 필수 | 무엇이 문제인지(기능 요청이면 왜 필요한지). 사용자 말에 근거가 있어야 한다 |
| 플랜 | 선택 | 속할 플랜 폴더 이름, `다음 플랜 후보`, 또는 `미정` |
| 원하는 결과 | 선택 | 끝났을 때 사용자가 보게 될 결과(화면·동작으로) |
| 우선순위 | 선택 | `높음`·`보통`·`낮음` |
| 발견 경위 | 선택 | 어디서 알게 됐는지 한 줄 |
| 대상 영역 | 선택 | 관련 파일·폴더. 짐작이면 끝에 `(추정)` |
| 세부 항목 | 선택 | 여러 개가 한 묶음이면 번호 목록 |
