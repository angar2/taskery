# /log-friction

## 개요

사용자가 작업 흐름 중 겪은 불편을 `.project/FRICTION_LOG.md`에 한 행 기록한다.
후속 조치 X — 분석 / 패턴 감지 / 룰 제안 자체를 본 스킬이 수행하지 않는다. 사용자가 직접 검토 후 판단한다.

## 호출 시점 (3가지 트리거)

1. **사용자 명시 호출** — `/log-friction "<불편 내용>"` 또는 인자 없이 호출
2. **사용자 불만 발화 캐치** — 메인 세션이 사용자 발화에서 불편·짜증·답답함 신호를 감지하면 *"이거 FRICTION_LOG에 등록할까?"* 제안한 후 사용자 OK 시 자동 발동
3. **task-close 직후 메인 자체 감지** — 작업 중 마찰 신호(동일 단계 재호출 / 실패 반복 / 사용자 부정 반응 누적 등)가 감지된 경우에만 *"이번 task에서 X 부분이 마찰이었어 보여 — 등록할까?"* 제안한 후 사용자 OK 시 발동. 감지 신호 없으면 호출 X

## 입력 처리

- 인자 형태 (사용자 명시 호출):
  - `/log-friction "<불편 내용>"` — 큰따옴표 인자에 본문 직접 전달
  - `/log-friction` — 인자 없이 호출 시 메인이 사용자에게 *"어떤 점이 불편했는지?"* 묻고 답변을 받음
- 자동 발동 시: 메인이 캐치한 발화 또는 감지한 마찰 신호를 사용자에게 *확인 차원*으로 보여주고 등록 본문에 대해 합의를 받음

## 단계

### Step 1 — 호출 경로 확인

호출 형태에 따라 분기한다.

- 직접 호출 (인자 있음) → 인자 본문을 등록 후보로 사용
- 직접 호출 (인자 없음) → 사용자에게 불편 내용을 질문
- 자동 발동 (불만 발화 캐치) → 캐치한 발화를 등록 후보로 보여주고 사용자 합의
- 자동 발동 (task-close 자체 감지) → 감지한 마찰 신호를 보여주고 사용자 합의

### Step 2 — 등록 본문 확정

사용자가 합의한 내용을 한 행(1~3 문장 이내)으로 정리한다.

포맷:

```
- YYYY-MM-DD | <맥락 — TASK 번호 또는 호출 시점> | <불편 내용 요약>
```

### Step 3 — FRICTION_LOG.md 한 행 추가

`.project/FRICTION_LOG.md`를 Read한 후 마지막 행 다음에 신규 행을 Append(Edit)한다.

**파일이 없으면 아래 골격을 먼저 Write한 후 첫 행을 작성한다.** (taskery는 이 파일을 배포하지 않는다 — 첫 기록 시점에 생긴다.)

```markdown
# FRICTION_LOG

> 사용자가 작업 흐름 중 겪은 불편 / 한계 / 짚이는 부분의 누적.
> `/log-friction` 스킬이 사용자 합의 후 한 행씩 추가한다.

**사용 규칙**:
- 한 행에 한 불편
- 손수 편집 X — 메인이 대화로 적음
- 사용자 명시 호출 / 사용자 불만 발화 캐치 / task-close 직후 마찰 신호 자체 감지 시 추가

---

## 불편 누적

| 날짜 | 불편 | 맥락 (어느 task / 스킬 / 카테고리) |
|------|------|-----------------------------------|
```

### Step 4 — 결과 보고

```
✅ /log-friction 완료
- 추가된 행: <등록 본문>
- 누적 행 수: <N>건
- 다음 호출: 사용자 명시 / 불만 발화 캐치 / task-close 자체 감지 중 하나
```

## 도구 가이드

- **Read**: `.project/FRICTION_LOG.md` 정독
- **Edit**: 마지막 행 다음에 신규 행 Append
- **AskUserQuestion**: Step 1·2 사용자 합의

## 주의사항

- 본 스킬은 *기록 행위*만 수행한다. 패턴 분석 / PLAYBOOK 매핑 / 룰 제안 X.
- task-close 자체 감지 트리거는 *마찰 신호 감지* 시에만 발동한다. 감지 없는 task-close에서 prompt 강제 X.
- 사용자 합의 없이 자동 등록 X. 자동 발동 경로도 반드시 사용자 OK 후 기록한다.
- 메인 자체 판단으로 등록 본문을 임의 가공·확장 X. 사용자 발화 또는 감지한 신호를 *그대로 인용* 원칙.
