# task-init

새 태스크를 여는 단계다. 판단은 아래를 따르고, 번호·분기·문서·기록은 명령이 한다.

- 태스크를 여는 쪽이 부른다. 오케스트레이션이 맡긴 태스크의 수행 세션은 task-plan부터 한다.
- 요청이나 백로그 항목(`backlog-get`)을 읽고, 태스크 하나로 묶을 범위·유형·크기(small·medium·large)·이름을 정한다. 백로그 항목을 옮기면 `--from BL-3,BL-7`로, `PLAN.md` 목록의 항목을 열면 `--item <항목 번호>`로 넘긴다.
- 스위치(기획·개발·테스트)는 기본이 모두 켜짐이다. 사용자가 말했거나 요청에서 강하게 유추될 때만(예: 시나리오대로 시험만 하는 태스크 → 개발 꺼짐) 한 줄로 묻고 정한다. 개발과 테스트를 둘 다 끌 수는 없다.
- 진행 범위는 사용자가 말한 대로 넘긴다. 말하지 않았으면 한 단계다.
- `prepare-task`를 부른다. 워크트리·브랜치 생략(`--no-worktree`·`--no-branch`)은 사용자가 명시했을 때만 넘기고, 먼저 제안하지 않는다.
- 직접 수행이면 만들어진 워크트리로 들어가 이어 간다(Claude Code는 EnterWorktree). Codex는 워크트리로 옮겨 갈 수 없으므로 워크트리 경로를 알리고 멈춘다(사용자가 그 워크트리에서 Codex를 연다). 사용자가 워크트리를 생략했으면 본진에서 그대로 이어 간다. 범위가 한 단계면 여기서 멈추고 보고한다.

## 부르는 명령

- `backlog-get` → `prepare-task`
