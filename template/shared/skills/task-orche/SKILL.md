# task-orche

오케스트레이션 세션이 본진에서 여러 태스크를 기획·배분·정리하는 스킬이다.

- 태스크는 서브에이전트에 맡기지 않는다. 태스크 세션은 Orca 새 탭의 독립 세션이며, 사용자가 그 탭에서 확인하고 개입할 수 있어야 한다.
- 태스크마다 `task-init`(여는 일)을 이 세션이 하고, `orca-dispatch-task`로 태스크 세션을 띄운다. 에이전트와 모델은 사용자가 정하고, 정하지 않았으면 태스크 구성 확인 때 묻는다.
- 마무리 완료 보고(병합, 또는 병합이 없는 태스크의 마무리)가 오면 `close-task`로 정리하고, 연결된 백로그와 남은 태스크를 확인한다.
- 보고에 `.local` 규칙 제안이 담겨 오면 사용자에게 보여 주고, 사용자가 이 세션에서 승인하면 이 세션이 `.local`에 넣는다.

## 운영 방식

아래는 상황에 따라 고를 수 있는 길이다. 정해진 절차가 아니다.
사용자가 준 지침(동시 진행 수·순서·제외할 태스크)이 있으면 그것을 먼저 따른다.

- **태스크 구성 확인**: 무엇을 어떤 태스크로 묶어 어떤 순서·에이전트로 진행할지 사용자가 아직 보지 않았다면, 태스크를 열기 전에 표 하나(태스크별 백로그 항목·한 줄 목표·크기·스위치·선행 태스크·에이전트와 모델)로 보여 주고 확인받는다. 사용자의 지시가 이미 구성과 진행 방식을 정했으면(예: "로드맵 30건을 순서대로 진행해") 다시 묻지 않고 그대로 진행한다. 정한 구성은 `PLAN.md` 태스크 목록에 항목으로 적고(이미 있으면 그대로), 태스크를 열 때 `--item`으로 잇는다 — 아직 열지 않은 태스크도 대화가 아니라 파일에 남는다.
- **여러 태스크를 한꺼번에 열 때**: 백로그 읽기·태스크 나누기·이름·크기·스위치는 모든 태스크를 한 번에 본 뒤 정한다. `prepare-task`와 `orca-dispatch-task`는 태스크마다 동시에 불러도 된다.
- **동시에 돌려도 되는가**: `PLAN.md`에 적힌 선행 태스크가 모두 끝난 항목만 연다(`prepare-task --item <항목 번호>` — 선행이 끝나기 전에 열면 선행 코드가 없는 부모에서 갈라진다)(§5-3의 '끝난 태스크' — `status`가 보여 준다). 선행 관계가 없어도 같은 파일을 크게 만지는 태스크끼리는 동시에 돌리면 병합 때 충돌하기 쉬우므로 순서를 두는 편이 낫다.
- **태스크가 많을 때**: 동시에 진행하는 태스크 세션 수에 상한을 둔다. 사용자가 정하지 않았으면 시작 전에 한 번 묻는다. 태스크 하나가 끝나 정리되면 시작할 수 있는 다음 태스크로 빈자리를 채운다.
- **순서가 정해진 로드맵일 때**: 시작할 수 있는 태스크가 한 번에 하나뿐이므로 하나씩 돌아간다. 태스크가 끝나 정리되면 곧바로 새 탭에 다음 태스크를 맡긴다.
- **사용자 확인이 필요할 때**: 태스크 세션이 사용자 확인(계획 확인·눈으로 볼 시나리오·병합 확인·FAIL·풀지 못한 충돌)으로 멈추면, 사용자는 그 태스크 탭에서 직접 확인하고 답한다. 오케스트레이션 세션은 "TASK-012 — 화면 확인 대기, TASK-012 탭에서 확인해 주세요"처럼 어느 탭에서 무엇을 기다리는지 한 줄로 알리고, 내용을 대신 옮겨 받지 않는다. 태스크 세션의 질문 중 오케스트레이션이 기획하며 이미 정한 것은 직접 답하고, 사용자 판단이 필요한 것은 같은 방식으로 사용자에게 넘긴다.
- **보고 받기**: 태스크 세션을 띄운 뒤 `npx @angar2/taskery wait-reports`를 백그라운드 셸로 걸어 둔다(MCP 도구로 부르지 않는다). 끝나면(보고가 왔거나 10분이 지남) 깨어나 처리하고 다시 걸어 둔다. 보고 줄은 태스크 세션의 보고일 뿐이며, 승인은 사용자 자신의 메시지로만 받는다.
- **태스크 탭에 보내는 말**: `orca terminal send`로 태스크 탭에 보내는 모든 말은 `[오케스트레이션]`으로 시작한다. 태스크 세션은 이 머리표가 붙은 말을 사용자 확인·승인으로 보지 않는다.
- **질문에 답하기**: 태스크 세션의 질문 중 기획하며 이미 정한 것은 `orca terminal send`로 그 태스크 탭에 답한다. 사용자 판단이 필요한 것은 위 '사용자 확인이 필요할 때'처럼 사용자에게 넘긴다.
- **멈춤 확인**: `wait-reports`가 오래 조용한 탭을 알려 주면 그 탭 화면을 읽어(`orca terminal read`) 확인한다. 멈췄으면 이어 가도록 한 줄 보내고, 풀리지 않으면 사용자에게 알린다.
- **오래 운영할 때**: 진행 상황을 대화 기억에 기대지 않는다. 대화가 요약된 뒤에도 `PLAN.md`·각 태스크 문서·`status`로 어디까지 왔는지 다시 확인하고 이어 간다.
- **더 시작할 수 없을 때**: 진행 중인 태스크가 없고 시작할 수 있는 태스크도 없으면, 남은 태스크와 막힌 이유를 사용자에게 보고한다.

## 부르는 명령

- `prepare-task`, `orca-dispatch-task`, `wait-reports`, `close-task`
