# project-init

프로젝트를 taskery로 시작하는 단계다. 처음 한 번만 쓴다.

- 처음 한 번 쓴다. 받은 기획 문서가 있으면 그것을 읽고, 없으면 핵심만 묻는다: 무엇을, 누가 쓰는지, 핵심 기능, 기술 스택.
- taskery가 설치돼 있지 않으면 `init`을 부른다(빈 폴더면 `init`이 git 시작·첫 커밋·부모 브랜치까지 만든다. 파일은 있는데 git이나 커밋이 없으면 `init`이 멈추므로, 무엇을 첫 커밋에 넣을지 사용자와 정해 첫 커밋을 만든 뒤 다시 부른다).
- 쓴다: `AGENTS.md`의 프로젝트 정보(이름·타입·소개), `PROJECT.md` 한 장 요약(무엇·왜·범위·기술 스택·구조 요점과 연관 정보), `GLOSSARY.md`(핵심 용어와 코드 이름).
- 제품 문서(`spec/`)는 기획에 내용이 있는 것만 만든다. 빈 틀을 만들지 않는다.
- 코드 테스트 명령을 리포를 보고 정해 `test-code --register "<명령>"`으로 등록한다. 화면을 켜는 테스트는 넣지 않는다. 코드가 아직 없으면 건너뛴다 — 첫 `test-code`가 등록을 요구하며 멈추면 그때 등록한다.
- `TEST_RULE.local.md`·`DEV_RULE.local.md`에 아는 내용만 채운다.
- 첫 플랜을 만든다(`plan-init`과 같은 일).
- 만든 것, 태스크 목록, 다음 할 일(직접 진행 또는 오케스트레이션)을 보고한다.

## 부르는 명령

- `init` (설치돼 있지 않을 때, CLI만) · `test-code --register` · `plan-init`
